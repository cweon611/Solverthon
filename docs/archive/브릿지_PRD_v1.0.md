# 「브릿지(Bridge)」 PRD

**초기 창업기업을 위한 푸시형 지원사업·법정의무 알림 서비스**

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 대회 | 2026 전남광주 청년 AI 솔버톤 / B트랙 (기업 실무 현안) |
| 연관 세부주제 | B-08 정부지원사업 공고 자동 분석 (확장: 법정의무 영역 추가) |
| 팀 | 코스모스 |
| 산출물 | 웹 서비스 (공개 배포 URL, 더미데이터 기반) |

---

## 0. 이 문서를 읽는 AI에게

이 문서는 **바이브코딩용 명세서**입니다. 아래 원칙을 반드시 지켜주세요.

1. **§4 AI 역할 경계**를 위반하지 마세요. 자격 판정과 마감일 계산은 절대 LLM에게 시키지 않습니다. 결정론적 코드로만 구현합니다.
2. 화면은 **P0 → P1 → P2 순서**로 구현합니다. P0만 완성돼도 데모가 성립해야 합니다.
3. 모든 배포본에는 **더미데이터만** 사용합니다. 실제 기업 데이터를 넣지 않습니다.
4. 법령 정보는 **하드코딩된 시드 데이터**이며, 화면에 항상 "확인 기준일"과 면책 문구를 함께 노출합니다.
5. 막히면 임의로 범위를 넓히지 말고, §11 비범위(Out of Scope)를 확인하세요.

## 1. 문제 정의

### 1.1 타깃 사용자

| 구분 | 조건 |
|---|---|
| 업력 | 3년 미만 |
| 규모 | 상시근로자 10인 미만 |
| 지역 | 광주·전남 (확장 가능) |
| 특징 | 대표가 영업·회계·인사를 겸업, 전담 인력 없음 |

### 1.2 핵심 문제: "모르는 것을 모른다"

검색은 **질문을 만들 수 있는 사람만** 쓸 수 있는 도구입니다.

- 임금명세서 교부 의무를 모르는 대표는 "임금명세서"를 검색하지 않습니다.
- 중소기업확인서 발급에 2~4주가 걸린다는 걸 모르면, 공고를 발견한 시점에 이미 늦습니다.
- 기업마당·K-Startup·소진공·중진공·지자체 등 10곳 이상을 매일 확인하는 건 1인 대표에게 불가능합니다.

따라서 **검색형(Pull)이 아니라 푸시형(Push)** 이어야 합니다. 사용자가 묻지 않아도, 프로필 기반으로 "지금 당신에게 해당하는 것"을 먼저 밀어줍니다.

### 1.3 비용 구조의 비대칭

| 축 | 놓쳤을 때 | 사용자 인지도 |
|---|---|---|
| 지원사업 | 기회손실 (돈을 못 받음) | 높음 |
| 법정의무 | 실손실 (과태료·가산세가 나감) | **낮음** |

기존 서비스는 전부 지원사업만 다룹니다. **브릿지는 두 축을 하나의 타임라인에 놓습니다.** 이것이 핵심 차별점입니다.

## 2. 제품 정의

### 2.1 한 줄 정의

> 사업자 정보 7개만 입력하면, 받을 수 있는 지원사업과 지켜야 할 법적 의무를 마감일 순으로 한 화면에 밀어주는 웹 서비스.

### 2.2 핵심 사용자 시나리오 (데모 시나리오)

**페르소나: 김창업 / 광주 소재 전자부품 제조업 / 업력 14개월 / 대표 1인 → 첫 직원 채용 예정**

1. 온보딩에서 7개 항목 입력 (2분)
2. 대시보드에 통합 타임라인 표시
   - 🟠 D-9 · 광주 청년 일자리 도약 장려금 — *신청 가능 (요건 6/6 충족)*
   - 🔴 D-3 · 원천세 신고·납부 — *매월 10일*
   - ⚪ D-21 · 부가가치세 예정신고
3. **"직원 채용 예정" 토글을 켠다** → 타임라인이 즉시 재계산되며 5개 항목이 새로 나타남
   - 근로계약서 서면 교부, 임금명세서 교부, 4대보험 취득신고(14일 이내), 근로자명부 작성, 청년채용 지원사업 3건
4. 지원사업 카드 클릭 → **요건별 판정표** (✅가능 / ❌불가 / ⚠️확인필요 + 각각의 근거)
5. "준비서류 리드타임" 탭 → 중소기업확인서 발급에 최대 20일 소요 → **역산 알림: 오늘 신청해야 마감 전 도착**

> 이 시나리오의 3번이 발표의 하이라이트입니다. "첫 채용"은 지원사업과 법정의무가 **동시에 폭발하는 유일한 시점**이라, 브릿지의 두 축을 한 장면에 보여줍니다.

## 3. 데이터 모델

### 3.1 `company_profile` (사용자 입력)

```ts
interface CompanyProfile {
  id: string;
  business_type: 'individual' | 'corporation';   // 개인/법인
  industry_code: string;                          // 표준산업분류 대분류 코드
  region_code: string;                            // 법정동 시도 코드 (광주 29, 전남 46)
  established_at: string;                         // YYYY-MM-DD
  employee_count: number;
  annual_revenue_krw: number | null;              // null 허용 → 판정 시 '확인필요'
  is_vat_exempt: boolean;                         // 면세사업자 여부

  // 이벤트 플래그 (타임라인 재계산 트리거)
  flags: {
    hiring_planned: boolean;
    has_online_sales: boolean;
    handles_personal_data: boolean;
    is_food_business: boolean;
  };
}
```

> **파생 필드는 저장하지 말고 계산하세요.** `business_age_months`는 `established_at` 기준으로 조회 시점에 계산합니다.

### 3.2 `program` (지원사업)

```ts
interface Program {
  id: string;
  source: 'bizinfo' | 'kstartup' | 'local';
  title: string;
  organization: string;
  apply_start: string;
  apply_end: string;
  support_amount_text: string;
  original_url: string;

  eligibility: ConditionGroup;       // §4.2 — AI가 생성, 사람이 검수
  required_documents: RequiredDoc[];
  embedding: number[];               // 중복제거용 (1536차원)
  duplicate_of: string | null;
  parsed_at: string;
  review_status: 'ai_draft' | 'human_verified';
}

interface RequiredDoc {
  name: string;                      // "중소기업확인서"
  issuer: string;                    // "중소기업현황정보시스템"
  lead_time_days: number;            // 20  ← 리드타임 역산의 핵심
  issue_url: string;
}
```

### 3.3 `obligation` (법정의무) — 시드 데이터

```ts
interface Obligation {
  id: string;                        // "OBL-LABOR-001"
  category: 'labor' | 'tax' | 'permit' | 'privacy';
  title: string;
  what: string;                      // 무엇을 해야 하는가 (1문장)
  penalty: string;                   // 안 하면 어떻게 되는가
  legal_basis: string;               // "근로기준법 제17조"
  legal_checked_at: string;          // 법령 확인 기준일 ← 화면 필수 노출
  how_to_url: string;

  applies_if: ConditionGroup;        // 이 프로필에 해당하는가
  schedule: ScheduleRule;            // 언제까지인가
}

type ScheduleRule =
  | { type: 'monthly'; day: number }                          // 원천세: 매월 10일
  | { type: 'annual'; month: number; day: number }            // 종소세: 5월 31일
  | { type: 'semiannual'; months: number[]; day: number }     // 부가세: 1월·7월 25일
  | { type: 'event_relative'; event: string; offset_days: number }; // 4대보험: 입사 +14일
```

**시드 데이터 최소 구성 (16건):**

| 카테고리 | 항목 |
|---|---|
| 노무 (5) | 근로계약서 서면 교부 / 임금명세서 교부 / 4대보험 취득신고 / 근로자명부·임금대장 보존 / 법정의무교육(성희롱예방·산업안전) |
| 세무 (6) | 원천세 / 부가가치세 / 종합소득세·법인세 / 간이지급명세서 / 사업장현황신고(면세) / 인건비 신고 |
| 인허가 (3) | 통신판매업 신고 / 식품 영업신고·위생교육 / 사업자등록 정보 변경신고 |
| 개인정보 (2) | 개인정보처리방침 게시 / 전자상거래법 표시사항 |

> ⚠️ 시드 데이터의 조문 번호·시행일·과태료 금액은 **국가법령정보센터(law.go.kr)에서 반드시 교차 확인**한 뒤 입력하고, `legal_checked_at`에 확인 날짜를 기록하세요. 확인 전에는 `legal_basis`를 비워두고 화면에 "확인 중"으로 표시합니다.

## 4. AI 역할 경계 ★ 가장 중요한 섹션

### 4.1 무엇을 AI에게 시키고, 무엇을 안 시키는가

| 작업 | 담당 | 이유 |
|---|---|---|
| 공고 원문(비정형 텍스트) → 구조화 JSON 변환 | **Claude API** | 문장을 읽는 일. LLM의 본령 |
| 서로 다른 기관의 동일 공고 중복 판별 | **임베딩 유사도** | 의미 기반 비교. 임계값 0.92 |
| 자격요건 충족 여부 판정 | **결정론적 룰 엔진** | 오판이 사용자 손실로 직결 |
| 마감일·D-day 계산 | **결정론적 코드** | 날짜 계산에 확률적 모델을 쓸 이유가 없음 |
| 법령 해석·적용 판단 | **하드코딩 시드 + 사람 검수** | AI가 법률 판단을 하면 안 됨 |

> **설계 근거 (심사 발표용):** AI가 자격을 잘못 판정하면 사용자는 신청 기회를 잃거나, 더 나쁘게는 의무를 놓쳐 과태료를 냅니다. 그래서 브릿지는 **AI를 "읽는 역할"에만 배치하고, "판단하는 역할"은 검증 가능한 코드에 맡깁니다.** 이 경계가 곧 신뢰성입니다.

### 4.2 조건 스키마 (판정의 공용 언어)

```ts
type ConditionGroup = {
  operator: 'AND' | 'OR';
  conditions: (Condition | ConditionGroup)[];
};

type Condition = {
  field: keyof FlatProfile;
  op: 'lt' | 'lte' | 'gt' | 'gte' | 'eq' | 'in' | 'not_in';
  value: number | string | string[];
  label: string;        // 사용자에게 보여줄 원문 요건 (예: "업력 3년 미만")
  source_text: string;  // 공고 원문에서 근거가 된 문장 ← 투명성의 핵심
};
```

### 4.3 판정 결과는 반드시 3-state

```ts
type Verdict = 'eligible' | 'ineligible' | 'needs_check';
```

**`needs_check`가 이 서비스의 안전장치입니다.**

- 프로필 값이 `null`이면 → `needs_check` (절대 `ineligible`로 처리하지 마세요)
- AI가 파싱한 조건에 `field` 매핑이 없으면 → `needs_check`
- 조건 텍스트가 모호하면(예: "지역 우수기업") → `needs_check` + 원문 표시

전체 판정은 이렇게 집계합니다:

```
하나라도 ineligible → 종합: 신청 불가
ineligible 없고 needs_check 있음 → 종합: 확인 필요
전부 eligible → 종합: 신청 가능
```

### 4.4 Claude API 파싱 프롬프트 명세

**입력:** 공고 원문 텍스트
**출력:** JSON only (마크다운 펜스 금지)

```
당신은 정부 지원사업 공고문을 구조화하는 파서입니다.
아래 공고문에서 정보를 추출해 JSON으로만 응답하세요. 설명이나 코드펜스를 붙이지 마세요.

규칙:
1. 원문에 명시되지 않은 조건은 절대 만들어내지 마세요.
2. 각 조건에는 근거가 된 원문 문장을 source_text에 그대로 담으세요.
3. 아래 field 목록에 매핑되지 않는 조건은 unmapped_conditions 배열에 원문 그대로 넣으세요.
   사용 가능 field: business_age_months, employee_count, region_code,
   industry_code, business_type, annual_revenue_krw
4. 확실하지 않으면 조건을 만들지 말고 unmapped_conditions로 보내세요.

출력 스키마: { ... }

공고문:
---
{{announcement_text}}
---
```

**호출 후 반드시:**
- `JSON.parse` 실패 시 1회 재시도 → 그래도 실패하면 `review_status: 'ai_draft'`로 저장하고 관리자 화면에 오류 표시
- `unmapped_conditions`가 비어있지 않으면 해당 프로그램의 판정 결과에 `needs_check`를 강제 주입

### 4.5 중복제거

기업마당과 K-Startup에 같은 사업이 중복 게시되는 경우가 많습니다.

```
1. title + organization + support_amount_text 를 이어붙여 임베딩 생성
2. pgvector 코사인 유사도 검색 (top 5)
3. 유사도 >= 0.92 AND 신청기간 겹침 → 중복 판정
4. 먼저 수집된 쪽을 canonical로, 나머지는 duplicate_of 설정
5. 목록에는 canonical만 노출하되, "기업마당·K-Startup 동시 게시" 뱃지 표시
```

> 데모 화면에서 이 과정을 **보여주세요**. 중복 판정된 쌍과 유사도 점수를 나란히 띄우는 것만으로 AI 활용도 점수가 올라갑니다.

## 5. 화면 명세

### P0 — 이것만 있어도 데모가 됩니다

#### S1. 온보딩 (`/onboarding`)

- 한 화면에 한 질문씩, 총 7단계 + 진행률 바
- 질문: 사업자 형태 / 업종 / 지역 / 개업일 / 상시근로자 수 / 연매출(선택, "모름" 버튼 필수) / 해당사항 체크박스
- **"모름"을 반드시 선택 가능하게** — 모른다고 해서 배제되면 안 됩니다
- 완료 시 localStorage + Supabase 저장, 즉시 S2로 이동

#### S2. 통합 타임라인 대시보드 (`/`) ★ 핵심 화면

```
┌─────────────────────────────────────────────┐
│  김창업님이 지금 챙겨야 할 일 · 8건          │
│  [ 전체 ] [ 지원사업 4 ] [ 법정의무 4 ]      │
├─────────────────────────────────────────────┤
│ 🔴 D-3   원천세 신고·납부          [법정의무]│
│          매월 10일 · 미납 시 가산세          │
├─────────────────────────────────────────────┤
│ 🟠 D-9   광주 청년 일자리 도약 장려금        │
│          ✅ 요건 6/6 충족 · 최대 1,200만원   │
├─────────────────────────────────────────────┤
│ 🟡 D-16  청년 디지털 일자리 사업             │
│          ⚠️ 확인 필요 2건                    │
└─────────────────────────────────────────────┘
```

- D-day 오름차순 정렬. 두 축을 **섞어서** 보여줍니다 (분리하면 차별점이 사라짐)
- 색: 🔴 D-7 이내 / 🟠 D-30 이내 / ⚪ 그 이후
- 상단에 **"직원 채용 예정" 토글** → 켜면 타임라인 즉시 재계산 (데모 하이라이트)

#### S3. 지원사업 상세 (`/program/[id]`)

요건별 판정표가 본체입니다.

| 요건 | 내 정보 | 판정 |
|---|---|---|
| 업력 3년 미만 | 14개월 | ✅ 충족 |
| 광주·전남 소재 | 광주광역시 | ✅ 충족 |
| 상시근로자 5인 이상 | 1명 | ❌ 미충족 |
| 지역 우수기업 | — | ⚠️ 원문 확인 필요 |

- 각 행 클릭 시 `source_text` (공고 원문 근거 문장) 펼침

## 6. 기술 스택

```
Frontend   Next.js 14 (App Router) + TypeScript + Tailwind CSS
DB         Supabase (Postgres + pgvector)
AI         Anthropic Claude API (파싱) / 임베딩 모델 (중복제거)
공공데이터  기업마당 지원사업정보 API, 창업진흥원 K-Startup API (15125364)
배포        Vercel
```

**필수 준수 사항:**

- API 키는 **서버 사이드에서만** 사용 (Next.js Route Handler 경유). 클라이언트 노출 금지
- 공공 API는 CORS 미지원 → 반드시 서버 경유
- 기업마당 API는 인증키 신청·승인 절차가 있으므로 **미리 발급**. 승인 지연 대비 캐시된 더미 공고 20건을 fallback으로 준비
- **기관 누리집 직접 크롤링 금지** (대회 규정). 공식 오픈 API만 사용

## 9. 룰 엔진 테스트 케이스

```ts
// 필수 통과 케이스
1. 모든 조건 충족 → 'eligible'
2. 한 조건 미충족 → 'ineligible' (다른 조건이 전부 충족이어도)
3. annual_revenue_krw === null 인 조건 → 'needs_check' (❌ ineligible 아님)
4. unmapped_conditions 존재 → 종합 판정에 needs_check 강제 주입
5. 중첩 ConditionGroup (AND 안의 OR) 정상 평가
6. business_age_months 는 established_at 기준 실시간 계산
7. 개업일이 미래 날짜 → 입력 단계에서 차단
```
